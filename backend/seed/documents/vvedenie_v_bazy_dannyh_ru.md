# Введение в базы данных — Глава 1

## 1.1 Что такое база данных и СУБД

**База данных (БД)** — это организованная совокупность данных, хранимая и
обрабатываемая в электронном виде. **Система управления базами данных
(СУБД)** — программное обеспечение, которое обеспечивает создание базы,
доступ к данным, их целостность и защиту. Примеры СУБД: PostgreSQL, MySQL,
SQLite, Oracle Database.

Главное преимущество СУБД перед хранением данных в обычных файлах —
централизованный контроль: одни и те же данные не дублируются в десятках
файлов, доступ разграничивается по ролям, а изменения выполняются надежно
даже при одновременной работе многих пользователей.

## 1.2 Реляционная модель данных

В реляционной модели данные представлены в виде **таблиц (отношений)**.
Каждая таблица состоит из **строк (кортежей)** и **столбцов (атрибутов)**.

- **Первичный ключ (PRIMARY KEY)** — атрибут или набор атрибутов, значение
  которого однозначно идентифицирует строку таблицы. Например, номер
  студенческого билета.
- **Внешний ключ (FOREIGN KEY)** — атрибут, ссылающийся на первичный ключ
  другой таблицы. Именно внешние ключи связывают таблицы между собой.

Пример: таблица `студенты (id, фамилия, группа_id)` связана с таблицей
`группы (id, название)` через внешний ключ `группа_id`. Такая связь
называется «один ко многим»: в одной группе учится много студентов.

## 1.3 Язык SQL

**SQL (Structured Query Language)** — стандартный язык работы с реляционными
базами данных. Основные группы команд:

- **DDL** (Data Definition Language): `CREATE TABLE`, `ALTER TABLE`,
  `DROP TABLE` — определение структуры данных;
- **DML** (Data Manipulation Language): `SELECT`, `INSERT`, `UPDATE`,
  `DELETE` — работа с самими данными.

Простейший запрос выборки:

```sql
SELECT фамилия, группа_id
FROM студенты
WHERE группа_id = 214
ORDER BY фамилия;
```

Запрос с соединением двух таблиц:

```sql
SELECT s.фамилия, g.название
FROM студенты s
JOIN группы g ON g.id = s.группа_id;
```

## 1.4 Целостность данных

СУБД поддерживает **ограничения целостности**, которые не позволяют записать
в базу противоречивые данные:

- `NOT NULL` — атрибут обязан иметь значение;
- `UNIQUE` — значения атрибута не должны повторяться;
- `FOREIGN KEY ... REFERENCES` — ссылка должна указывать на существующую
  строку (ссылочная целостность);
- `CHECK` — произвольное условие на значение (например, оценка от 0 до 100).

## 1.5 Нормализация (кратко)

**Нормализация** — процесс приведения структуры таблиц к виду, устраняющему
избыточность и аномалии обновления. Основные ступени:

- **1НФ** — все значения атомарны, нет повторяющихся групп;
- **2НФ** — нет частичных зависимостей от составного ключа;
- **3НФ** — нет транзитивных зависимостей (неключевой атрибут не зависит от
  другого неключевого атрибута).

Практическое правило: если одна и та же информация (например, телефон
преподавателя) повторяется во многих строках — таблицу стоит разделить.

## 1.6 Транзакции и свойства ACID

**Транзакция** — последовательность операций, которая выполняется как единое
целое: либо целиком, либо никак. Классический пример — перевод денег между
счетами: списание и зачисление должны либо произойти оба, либо не произойти
вовсе.

Свойства транзакций описываются аббревиатурой **ACID**:

- **Atomicity (атомарность)** — транзакция неделима;
- **Consistency (согласованность)** — база переходит из одного корректного
  состояния в другое;
- **Isolation (изолированность)** — параллельные транзакции не видят
  промежуточных состояний друг друга;
- **Durability (долговечность)** — после подтверждения (COMMIT) изменения
  сохраняются даже при сбое системы.

## Итоги главы

Реляционная база данных хранит данные в связанных таблицах, SQL служит
универсальным языком запросов, ограничения целостности защищают данные от
противоречий, а транзакции обеспечивают надежность изменений. В следующей
главе мы спроектируем учебную базу данных «библиотека» и напишем к ней первые
запросы.
